# Task 1 Observation
I implemented the Stop-and-Wait reliable data transfer protocol for this task.
The sender splits the input data into fixed-size packets of 8 bytes, each marked with a sequence number. The sender only sends one packet at a time and waits for the corresponding ACK before transmitting the next packet. If no ACK arrives, the sender continuously retransmits the current packet to simulate timeout.

The receiver keeps track of the expected sequence number. When it receives an in-order packet matching the expected sequence number, it appends the payload to the buffer and sends back an ACK. If the packet is duplicated or out-of-order, the receiver resends the last valid ACK, which prevents negative sequence number errors.

The theoretical minimal number of packets required for 2000 bytes is 250 (2000 / 8). In this test run, the channel sent 379 packets. Extra packets are caused by retransmissions for lost packets and duplicate packets generated by the unreliable channel.

Packet loss is the primary problem for raw transmission without retransmission. Duplicate packets and packet reordering are handled by sequence number checking and re-sending the latest ACK.
